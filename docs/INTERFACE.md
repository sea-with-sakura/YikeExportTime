# 界面与截图规范

## 建议截图

将截图放在 `assets/screenshots/`，提交前确认画面中没有 Cookie、完整请求 URL、本地用户名、目录路径或个人照片。

| 文件名 | 画面 | 用途 |
| --- | --- | --- |
| `export-empty.png` | 导出页的空白初始状态 | README 首图 |
| `export-complete.png` | 已完成导出，日志只保留汇总行 | 展示导出结果 |
| `write-summary.png` | 本地日期写入完成后的汇总 | 展示匹配、写入与同步结果 |

README 加入截图时使用：

```markdown
![导出页](assets/screenshots/export-empty.png)
```

## 界面设计建议

1. 导出页与本地写入页分别显示“日期来源”“匹配数量”“将写入数量”“跳过数量”，避免用户只能从长日志判断进度。
2. 写入页使用四段固定进度：扫描文件、识别已有日期、写入媒体元数据、同步 Windows 文件日期。每段显示完成数与总数。
3. 将 URL 与 Cookie 放入一个可折叠的“网页请求”区域，Cookie 默认隐藏，并在旁边标明“仅本次运行使用”。
4. 完成页提供简短结果卡片：匹配、写入、已有日期跳过、异常跳过、Windows 时间同步。日志保留为辅助信息。
5. 使用 `assets/yike-export-time.ico` 作为程序图标，使用 `assets/yike-export-time.png` 作为 GitHub 头像和 README 标志，保持仓库与桌面程序识别一致。

## 视觉方向

- 主色：深青绿色，表示媒体归档与可靠性。
- 强调色：珊瑚红，用于日期、错误和需要注意的状态。
- 页面背景：浅灰白；内容区使用清晰的边界和 8px 以下圆角。
- 日志不作为主要状态面板；主要状态用数字和进度条表达。
